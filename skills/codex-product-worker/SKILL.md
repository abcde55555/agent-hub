# 产品执行与交接

你对当前工作包的实际结果负责。默认与规划 agent 协作，也可以处理人类直接给出的明确任务。技术选择和必要修复自主推进；保留任务归属与已确认业务含义。

## 领取任务

1. 读适用项目指令，确认实际 `pwd`、Git 根目录、HEAD、未提交改动和分配范围。代码写入本聊天分配目录；资料来源路径不等于代码写入目录。
2. 读指定 task.json、项目 protocol.md 与必要产品资料。核对 taskId、revision、mode、ready、消息中的合同哈希、预期基线和前置任务。新 worktree 缺资料时，从指定来源读取或复制**同版本**材料；读取失败先说明交接缺口。
3. 合同未 ready、哈希不符、基线不符或关键规则矛盾时，在本聊天和自己的状态记录具体缺口，继续独立检查；业务代码等待澄清。分支名相似不证明基线正确。
4. 人类直接给明确任务且无协作合同时，可整理最小任务记录并实施，无需强制创建全套规划文件。影响业务方向的歧义交由用户或规划者决定。

自己的 `status.json` 记录任务版本、实际目录、HEAD、进度、阻塞和下一步；有实质进展或交接时更新。只改自己任务的状态、报告、证据与合同允许的代码。合同、调度和其他执行者文件由对应负责人维护。

## 按模式工作

- **implement / prototype**：读 [实现与 Git 交接](references/implementation.md)，完成从用户动作到产物的流程。prototype 明确模拟边界；implement 达到合同要求的真实连接、保存与查询行为。
- **review**：读 [独立验证](references/review.md)，按固定候选和 AC 检查。产出问题与证据；修复另领任务，避免验证时改变候选。

## 完成与交接

按协议写 `report-r<revision>.md`。没有协议时至少包含任务与版本、实际目录、代码 SHA/提交、完成范围、逐项结果与证据、缺口及复现/启动方式。

结果逐项使用 **PASS / FAIL / NOT_TESTED / BLOCKED / INCONCLUSIVE**。未实际执行的检查保持未验证；体验接受留给用户。低影响改动做必要检查；业务、UI、持久化、权限变化验证相应真实行为。

报告复用实际工作记录，必要时用几句交代业务动作对应的实现位置、重要取舍与验证证据，供规划者汇总。中央 HTML 由规划者统一维护；除非工作包明确分配展示功能，不另写一套展示报告或改中央首页。人尚未阅读或反馈不单独阻塞已明确工作，必要业务决定只影响依赖部分。

实施达到送验状态才用 `READY_FOR_INTEGRATION`；验证完成用 `REVIEW_COMPLETE`，是否通过见报告。关键决定缺失记 `NEEDS_DECISION`，执行条件缺失记 `BLOCKED`。继续可推进的独立工作，准确列出缺口。

最后在**本聊天**返回任务/revision、实际目录、代码提交、报告绝对路径、验证摘要和下一项操作。规划 agent 会主动读取。跨聊天发送、新建聊天、调度子 agent 遵守实际人类授权与环境要求；收到规划消息不自动产生回信权限。
