# 逆向工程

先对齐再动手。逆向的失败几乎都来自「猜目标」——拿到样本就开始反编译，最后产出一堆没有结论的代码。本件的规矩是：**四问开局 → 建 case → 路由 → 分阶段推进 → 复算验收**。

## 一、四问开局

接到任务先问清四件事，信息不足就澄清：

| # | 问题 | 要拿到的东西 |
|---|---|---|
| ① 目标 | 要还原/证明什么？ | 一句可验收的话。例：「还原 sign 参数的算法，能离线复算出同值」 |
| ② 动作 | 静态分析、重建复现，还是动态取证？ | 明确分析边界（本环境默认静态） |
| ③ 素材 | 有哪些样本、抓包、线索？ | 素材清单与绝对路径 |
| ④ 交付物 | 什么算完成？ | 报告 + 可复现步骤 + 复算脚本 |

## 二、建 case

先按 [CASE.md](CASE.md) 建 `work/<case>/`：**原始样本只读**，一切加工落在 `derived/`。
一目录多样本的批量任务走 [BATCH.md](BATCH.md)，每个目标一个 case。

## 四、分阶段推进

`triage → static → rebuild → report`，每阶段产物落 case 目录。

**triage** — 定格式、架构、保护态势。完成判据：能一句话说清「这是什么、有没有加壳、入口在哪」。
**static** — 按路由读分支文件、逐层剥离。完成判据：目标结论的每条支撑都指得出证据路径。
**rebuild** — 产出可运行的等价物（复算脚本 / 解混淆代码 / 重打包 APK）。完成判据：产物能跑起来并给出结果。
**report** — 按 [CASE.md](CASE.md) 的格式写结论。完成判据：每条 Finding 都指向 ≥1 条 Evidence，并给出第三方可照做的 Path。

## 五、验收门

- **证据**：每条结论标注来源。静态给 `文件:偏移/行号`，动态给 trace 片段。事实与推断分开陈述。
- **复算**：加密/签名算法的「还原完成」以**离线复算 byte 级一致**为准，且 **≥3 组独立样本**。细则见 [CRYPTO.md](CRYPTO.md)。
- **视图一致**：偏移结论注明来源视图（file offset / vaddr / smali 行号），同一结论内不混用。
- **穷尽**：批处理任务里每个目标都要有一行结论——成功、失败、或跳过并写明原因。

## 六、能力边界（如实标注）

- 加壳、白盒密码学、服务端下发的密钥：**纯静态无法完全还原**。报告写清「观察到什么、卡在哪、还需什么才能继续」，不要写成「已还原」。
- 本环境为静态栈（未装 Frida、无 root 设备）。确实需要运行时观测时，说明清楚并给出替代路径。
- 静态还原不出结果时，把已验证的部分和未决问题分开列出——部分结论同样是有价值的交付物。
